01 · 计算总图与权威边界

系统在当前搜索链中的职责不是它的职责
PostgreSQL来源、修订、当前可见内容、物品与任务；候选返回后按当前 serving 修订和删除状态批量核对。不做在线全文相关性或无界图遍历。
对象存储原文件、完整规范化正文、自然章节、模型矩阵与计算产物；引用必须从保存正文回读。摘要不能代替原文。
Elasticsearch自然章节及有出处语义对象的中英分析、BM25、短语、精确标题、范围过滤与高亮。高亮片段本身不是最终引用。
Neo4j概念、语义对象与所属物品的有界关系；返回路径和原文位置。不维护用户 Ontology，也不在线自由扩图。
MilvusDense、学习型 Sparse、独立多向量三个检索集合；子向量归并到物品。不判定当前文章来源是否仍可见。
DataCenter／AgentDataCenter 公布并执行 BGE 表示、排序及逻辑生成路由；BTW 的 tRPC-Agent-Go Runner 调用该受控地址。模型不直接扩大场景范围，也不把搜索变成长篇答案。
Kafka／ClickHouse内容与行为进入 Worker、离线反馈和样本聚合。普通在线搜索不扫描行为历史。
外部每次传入用户 Ontology。它提供检索上下文与图标签，不赋予新的资料访问范围；BTW 不回查或训练用户塔。搜索返回物品和证据，综合回答由独立问答接口完成。
BTW 的模型相关运行配置现在只有 DataCenter 地址。API 与 Worker 启动时从 DataCenter 读取当前表示、排序和逻辑生成模型合同；规划、证据判断、问答、离线理解及 BGE 编码均经同一受控地址。服务身份由部署层文件提供，不在 BTW YAML 保存模型名、空间、供应商地址或密钥。DataCenter 不可用或合同不匹配时明确失败。

02 · 输入、候选单位与可见性

请求合同

POST /api/search 接收请求标识、Ontology、场景、query、可选 context、结果数量和 search_level。缺省档位为 balanced。query 为空时当前只回退到图画像排序后的首个词项；context 会进入规划模型，但不能单独替代检索问题。场景由服务端决定根物品类型、候选预算、RRF 常数、超时和交付数量；客户端不能扩充范围。

Ontology 在哪里真的起作用

有明确 query 时，节点标签会进入图检索种子，整个 Ontology 会进入规划模型，标题／摘要／主题与 Ontology 词项的包含关系成为可选排序特征。query 为空时当前实现只取排序后第一个图画像词项充当问题，不是对全部图节点做完整意图综合。搜索三档不把可选用户向量参与召回。

粒度持久身份与来源召回与交付语义
整书／文章根物品指向不可变来源修订；完整正文与目录另存。可以直接返回根物品；网站场景在检索前用根类型排除书籍。
自然章节章节是原文结构，有顺序、标题、路径和正文区间。全文索引的一行可对应章节，但它不是固定长度 chunk 物品。
语义对象概念／事实／方法有自己的物品 ID、根物品归属、原文位置与关系。可独立成为命中；同一本书的不同语义对象当前仍可能分别占用列表名额。
计算窗口／子向量窗口为长自然结构的模型输入；子向量归属窗口和物品，矩阵保留在对象存储。不是独立推荐物品；查询词元的多向量候选先归并到物品 ID。

外部索引只提供候选。每条候选带物品 ID、根类型、来源修订和原文位置；在线对有限候选批量核对 PostgreSQL 的当前 serving 修订，过时或删除的候选即使仍在索引中也不能返回。注意：过时行若占满检索后端 Top-K，会挤掉新的有效候选；当前没有自适应补召回。

有效候选 = 后端命中 ∩ 当前可见物品 ∩ 场景允许的根类型 ∩ 命中所指来源修订

普通结果包含 hits、每路原始 scores、实际执行 path、可回读 citations、status 和 warnings。三档搜索最终 hit.score 均为最后一层 RRF 名次分；已加载的 ranker 只改变表达内名次，其原始输出保留在 scores.ranker，不能把最终分解释为概率。

03 · 三档策略：调用顺序和预算不是名称差异

fast · 直接
原问题→全文→关系→引用

没有生成模型、BGE、向量通道、模型排序或第二轮搜索。

balanced · 一次规划
规划→多表达→多路召回→融合

原问题保留，最多追加两个表达；各表达并行，单轮结束。

deep · 迭代取证
拆解→多路召回→证据→缺口→再查

增加独立多向量与有限窗口核查；有依据缺口才继续。

fast 的真实策略边界
Elasticsearch 先查标题／摘要／正文，命中标题、原问题和 Ontology 节点标签组成 Neo4j 种子；图最多走一跳。两路按排名融合，再核对当前修订、读回原文。词法命中可覆盖稀有名称、引号短语；它不能主动理解同义措辞。
balanced 的真实策略边界
一次模型规划输出检索表达，不产生新事实。原问题及最多两个变体分别执行全文、图、Dense、Sparse；先表达内融合，再跨表达按名次融合。规划失败时仍可用原问题检索，但状态为 degraded；没有按首轮结果继续改写。
deep 的真实策略边界
首轮最多 5 条表达，增加独立多向量；读回有限原文后，模型只对这些引用判断表达是否被支持。仍有缺口才带缺口规划下一轮。当前“子问题”是字符串检索表达，没有单独的证据条件 schema；最多 3 轮、12 条不同表达。

04 · 检索算子：输入、得分和候选如何产生

4.1 全文：字段化 BM25，不是 BTW 自写分词器

索引行来自完整自然章节以及语义对象引用的原文。标题以 CJK 与 standard 子字段分析，摘要和正文以 CJK 分析；正文存 offsets 供高亮。当前请求是 best_fields 多字段匹配：标题加权 3，摘要加权 2，正文加权 1；标准标题子字段加权 3。标题完全相等的 keyword 子字段额外 boost 5；用户引号内短语产生正文短语查询，boost 3。根类型过滤在 Elasticsearch 内执行，然后按物品 ID 折叠候选。

全文候选 = BM25(标题、摘要、正文) ∪ 精确标题 ∪ 引号短语；原始 _score 仅在全文通道内排序

Elasticsearch 高亮只为候选定位。交付引用时，服务端去掉高亮标签，在保存的章节正文中重新查找这一文本，得到 Unicode 码点半开区间；找不到则发 warning，不把高亮直接当证据。当前定位从章节开头寻找首个相同片段；若一章多次出现相同文字，引用真实但可能不是原搜索行最接近的那一次。

4.2 内容图：精确概念种子＋有界路径

概念标签目前按小写、去首尾空白规范化。种子来自原问题、Ontology 节点标签和全文候选标题；去重排序后最多取 8 个标签。图只走“概念提及、归属、语义关系”三类边，使用服务端指定的 1／2／3 跳上限和根类型过滤。语义关系及对象有来源区间，根物品命中可沿路径带回位置。

图候选原始分 = 1 / 路径跳数；真正进入最终排序的是图通道名次，而不是这个分直接与 BM25 相加

这是精确标签图检索，当前没有独立的实体链接、别名消歧或图嵌入召回。种子上限和精确匹配会影响长问题的图召回，Benchmark 中规则拓扑的毫秒级结果不能说明语义图质量。

4.3 Dense：语义近邻

BGE-M3 对查询与物品计算 Dense 表示。书籍自然章节过长时，Worker 在章节内以配置的 2,048 码点计算窗口读取，模型服务在自身 token 上限内继续分窗；这些窗口只作为同一根物品的检索表示。Milvus 中 Dense 以 1,024 维 float32 和内积度量检索，基线索引路线为 DISKANN；一次查询中同物品多个窗口取最佳命中后归并。

Dense(q,d) = q · d　　（当前实现使用模型输出和内积，不额外伪造相似度）

Dense 解决措辞变化，但若物品有多个窗口，线上取得的是被 ANN 找到的局部表示；当前没有训练出的全书跨章节聚合向量。

4.4 学习型 Sparse：模型词权重＋倒排

同一 BGE-M3 输出 token ID 到非零权重的稀疏向量，索引为 Milvus Sparse 倒排、内积查询。只有查询与物品共有的 token ID 贡献分数；这一路与 Elasticsearch BM25 是不同的编码器和评分语义，不能混称“两个 BM25”。balanced 查询编码选择性请求 Dense＋Sparse，不计算该档不会使用的多向量矩阵。

Sparse(q,d) = Σt ∈ nonzero(q) ∩ nonzero(d) wq,t × wd,t

4.5 多向量：独立召回，再核查一个命中窗口

deep 为每个查询子向量单独检索 Milvus 多向量集合。每个查询向量的命中行先对同物品取最大分，再对所有查询子向量求平均；没有返回该物品的查询向量在当前近似聚合中相当于零贡献。它不是“Dense 候选上的后处理”，但每词元一次近邻调用也会放大网络开销。

近似分(q,d) = [Σi maxj ∈ ANNi(d)(qi · dj)] / |q|
精确窗口 MaxSim(q,D) = [Σi maxj ∈ D(qi · dj)] / |q|

初排靠前最多 20 个、且已有多向量命中位置的候选，会从对象存储读取该 ANN 指定窗口的保存矩阵计算 MaxSim；不是扫描整本书全部矩阵。精确值写进多向量特征，同时保留 ANN 近似值。当前无搜索排序模型时，这一步不重算 RRF 总分，也不凭精确值自动改变名次；仅在配置了排序模型且该特征被模型使用时可能影响表达内重排。

检索后端的 Top-K 先对“行”发生，再对“物品”归并。长书子向量多时仍可能占据较多行名额；当前没有物品级自适应补候选。语义对象与根物品也有不同 ID，不能说所有书内信息已被根物品级列表去重。

05 · 两层融合、可选排序与特征实际含义

表达内：按通道名次

全文、图、Dense、Sparse、Multi 的原始分尺度不同。当前先过滤掉不可见修订，再为每个物品汇总各路 RRF。每一路同物品只计第一次出现；最后按候选分裁到场景候选上限。fast 只有全文＋图，因此没有模型排序。

Sexpr(d) = Σlane 命中 d 1 / (K + ranklane(d) + 1)，示例 K = 60

表达间：按表达名次

balanced／deep 的原问题和规划表达各自完整执行上述流程，再以物品 ID 合并表达结果，按表达内名次再次 RRF。一个表达产生更多候选，不会因为原始分值尺度高而直接压过其他表达；但同物品在更多表达中命中仍会累积排名贡献。

Sfinal(d) = Σexpression 命中 d 1 / (K + rankexpr(d) + 1)

如果部署配置指定搜索排序模型，当前实现先在每个表达内部用 LightGBM 推理重排，随后跨表达仍按名次融合；它不是先合并全部表达候选再做一次全局重排。示例部署配置没有启用搜索排序模型，因此默认搜索实际交付的是 RRF 结果，不能把实验中的融合名次称为模型效果。

搜索排序特征（当前顺序）真实来源与缺失语义
全文分、图分Elasticsearch _score；图候选为 1／跳数。未命中时特征值为 0。
Dense、Sparse、多向量分分别来自 BGE 表示检索；deep 靠前窗口的多向量分可被精确 MaxSim 覆盖。
RRF 分该表达内多个通道的名次融合分；不等于不同模型原始分加和。
图画像重叠Ontology 词项是否被物品标题／摘要／主题包含的计数；名称虽叫 graph overlap，当前不是 Neo4j 路径特征。
质量与质量缺失离线理解给出的可选判断质量；未给出时质量数值为 0，缺失标记为 1。
全文缺失、多向量缺失各通道未产生命中时为 1；模型需在训练和在线使用同一特征顺序。
当前 11 个搜索特征包含通道分、RRF、图画像文本重叠、质量及缺失标记。表达间融合时同物品的各路原始特征可能由后到表达覆盖；最终列表主要由表达间名次决定。全局学习融合尚未实现或评测。
一个可手算的 RRF 例子（说明公式，不是线上结果）

假设 K=60，物品 A 在全文排第 1、Dense 排第 3，则表达内得分为 1/61＋1/63≈0.03226。物品 B 只在全文排第 2，得分 1/62≈0.01613。若另一个表达让 B 排第 1、A 排第 5，最终跨表达按新名次再融合：A 得 1/61＋1/65，B 得 1/62＋1/61。这个结果不能解释为两物品的相关概率。

06 · deep 的证据状态机与引用闭环

  1. 规划模型读取原问题、上下文和本轮 Ontology，输出至多 4 条额外检索表达；原问题始终保留。模型文字不能指定更大的资料范围或图跳数。
  2. 每条表达走全文、图、Dense、Sparse、Multi；表达间融合后，读取各表达靠前最多 10 个候选的保存原文。全文高亮还要在原文中重新定位；其他命中按已保存位置有界读取。
  3. 证据判断最多接收 16 条引用，每条引文最多 512 个 Unicode 码点，且受场景证据字节预算限制。模型返回“目标表达索引 → 引用 ID”；引用 ID 必须确实存在于本轮回读的集合中。
  4. 未被支持的目标表达成为缺口。若还有轮次和表达预算，再用缺口请求更具体检索表达；最多 3 轮、12 条不同表达。取消、预算耗尽或证据已足够时停止。
  5. 结果按最终物品数裁剪引用。如果用于支持某目标的引用被最终裁掉，状态改为依据不足；模型判断失败则为降级，不把已执行的一轮伪装成完整 deep。
状态／事件搜索接口的真实交付
ok已执行路径内没有通道或证据判断失败；deep 所有目标表达在已回读引用中有支持。
degraded规划、单通道、精确核查或证据判断失败，保留已有物品与引用并说明警告。一次实测中证据判断 JSON 未闭合，报 unexpected EOF。
insufficient_evidence运行未出错，但预算内仍有目标表达缺少有效引用，或其支持引用在最终列表裁剪后不再交付。
依赖错误／取消全部通道不可用或请求 Context 被取消时返回错误；不能把它写成“没有相关内容”。

每条引用包含物品 ID、不可变来源修订、章节、码点起止和当时读到的文字，并给出可回读地址。现有闭环验证的是“模型引用了真实读过的片段”；它不等于事实真值评估，也不能保证多个来源互相独立。历史修订可能仍保留阅读能力，但在线命中只接受当前 serving 修订；删除会阻止公开阅读。

07 · 离线资料如何生产五路候选

阶段真实产物与处理逻辑策略影响
来源接纳Kafka 通用内容事件或书籍上传。原文件先入对象存储，再在事务中登记来源修订、事件和 Worker 任务；接纳成功才确认输入。重复与乱序由来源的业务修订处理；网站 URL 不触发爬虫。
自然结构EPUB 按阅读顺序保留目录与章节；UTF-8 TXT／Markdown 保留完整正文及可识别标题。保存码点位置、章节对象引用和阅读范围。固定长度模型窗口不变成持久化 chunk 物品；原文可独立阅读。
内容理解逐自然结构读取，长内容按临时窗口理解；模型给摘要、主题、语言、可选质量、概念／事实／方法及精确原文引语，再递归聚合摘要。语义对象与关系必须从输入窗口找到原文；不能截断后宣称全文覆盖。
三种表示BGE-M3 对根物品的计算窗口和语义对象引语分别编码 Dense／Sparse／词元矩阵；编码产物可按物品与位置复用。整书不是一个虚构的单 Dense 向量；窗口与子向量归属根物品和真实位置。
外部投影全文索引保存章节全文及语义引语；内容图保存根、语义对象、概念与有位置的关系；向量库按行写入三通道。向量索引与全文／图都可以暂时含旧行，在线权威可见性由 PostgreSQL 决定。
发布与恢复只有解析章节全部理解完成、投影成功、Worker 租约和目标修订仍有效才更新当前 serving 修订；旧索引异步清理。更新期间旧完成内容仍可见；删除立即从权威库隐藏，迟到 Worker 不能复活旧内容。
当前全文投影对单个自然章节设置 64 MiB 配置上限；超过上限会明确报加工错误并保留已接纳原文件，不会静默截断。对象存储的全文与计算矩阵容量要分开计量。

08 · 样本、排序训练与效果闭环

冷启动样本生产

内容理解可生成有原文引语的查询—正例。样本构建再用真实全文、图和向量通道采困难负例，读取候选原文，让教师模型给相关性等级。合成、教师、人审和行为标签要分开统计；源与重复簇决定训练／验证隔离。

真实可训练消费者

搜索排序基线为 LightGBM LambdaRank、NDCG 目标，特征顺序与在线 11 维合同一致。DataCenter 管理真实排序产物并在当前 manifest 中公布；未公布搜索 ranker 时在线仍用 RRF，不把固定业务权重叫作学习排序。

这条链的目标是避免同一本书的相近引语跨训练／验证泄漏。行为样本只有真实展示、观察窗口结束等条件成立才可当负例；仅产生候选不等于曝光。当前 Benchmark 的 SciFact 测试标注没有用于训练，也没有为三档在完整语料上完成 ranker 消融。

应固定的实验变量要比较的指标当前证据
固定候选，比较 RRF 与搜索排序模型NDCG@10、MRR@10、校准与缺失特征影响真实训练／加载链可运行；尚无目标语料的在线排序增益结论。
固定排序，逐一增加全文／图／Dense／Sparse／MultiRecall@K、独立增量、长尾术语与跨章节覆盖只有全文完整语料与 24 篇正例必入表示对照，不能跨实验直接比高低。
固定语料和资源，改变策略档位最终 Recall／NDCG、引用支持率、p95/p99、模型调用、失败率三档目前只有一个物品的真实在线冒烟；尚无大语料三档同集对照。

09 · 亿级目标要按“子向量”而非仅按物品计数

当前每条多向量原始行是 1,024 维 float32，约 4,096 字节，且还要存 Dense、Sparse、索引元数据、原文、语义对象、副本和构建临时空间。SciFact 的 24 篇标题＋摘要样本实际产生 9,362 条子向量，平均约 390 条／篇；这不是长书的均值，也不可以直接推广到亿级。

原始多向量空间：计算中

公式仅为 N × T × 1,024 × 4 × R 字节。示例参数不是容量预测；真实书籍的词元数、索引结构、磁盘放大、RAM、删除回收和更新峰值尚未完成物理 Milvus 实测。线上只在受限候选窗口读取矩阵，不能把全书词元常驻 API 内存。

11 · 对策略研发最重要的未完成边界

当前行为不能据此声称下一项可证伪实验
图种子是精确标签，最多 8 个；语义对象有实际原文位置。已具备实体链接、别名归一、跨书知识推理或真实图召回收益。真实抽取关系的标注集上做图通道独立 Recall 与误连接审计。
每表达内部可用 LightGBM 排序，跨表达再按名次融合。已有全局学习融合、跨表达特征聚合或多目标最优排序。固定候选比较表达内 ranker、跨表达 RRF、全局候选 ranker 的 NDCG。
多向量每查询子向量独立检索；Top 20 命中窗口精确核查。已对整本书做完整 MaxSim，或精确核查必然改变最终名次。同一窗口的 ANN／Exact 数值差及长书物品级召回、网络调用数。
资料修订按 PostgreSQL 当前 serving 核对。旧索引不会挤占 Top-K，或删除清理没有延迟窗口。更新／删除占比递增时，测有效候选率和补召回需求。
全文高亮会重新回读原文，并在章节内找首个匹配片段。重复语句一定定位到搜索命中的那一次出现。构造同章重复短语，比较索引 offsets、保存原文位置与最终引用。
deep 最多 3 轮，判断只引用已经回读的保存正文。复杂问题已经有独立证据条件结构，或深档模型输出稳定可靠。构造首轮缺口、多源冲突与不可解问题，记录逐轮支持率与降级率。
物理 ES／Neo／PG 小样本已测；BGE 与生成模型实调。物理 Milvus DISKANN、Kafka／S3／ClickHouse 联测、百万／亿级容量或并发 SLA 已通过。同一完整语料的物理三档对照，记录索引／RAM／更新峰值和并发 p99。

这些是当前能力的边界，不是把已测单路分数外推成整个系统的结果。搜索策略的下一轮评审应以同一语料、相同相关性标注和明确资源预算为基础。
