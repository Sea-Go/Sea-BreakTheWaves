01 · 推荐主链

图注：召回由表示模型完成三路编码检索，排序为可选的排序模型推理——两者都不是生成模型。「生成」节点（高亮）是推荐全部链路中唯一的大模型调用，只出现在计划分支；网站列表分支从召回到交付全程不调用生成模型。计划场景不接受搜索等级参数，搜索三档的查询规划器与证据判断器不参与推荐。

网站列表

  • 各路召回前限制根类型为文章，书籍及其衍生对象不能进入候选。
  • 语义子对象可命中文章，但最终列表归并到根文章。
  • 按有效来源与重复簇去重，返回摘要及原文链接。
  • 调用表征与排序模型，不调用生成模型。

有据计划

  • 根据 Ontology、查询／上下文和服务端场景组织需求。
  • 复用候选、排序与原文工具；必要时继续受限取证。
  • 生成名称、目标、步骤、展示文本和引用。
  • 不执行任务／日历操作；依据不足要明确返回。

外部用户向量仅在与已部署物品投影的空间、维度和索引匹配时进入匹配通道。缺失／不匹配时使用真实图画像路径并说明，不能产生模拟用户向量。

02 · 文本如何变成三种表示

当前使用同一个 BGE-M3 编码器，在一次前向计算后输出三种表示。不是先调用三个生成模型，也不是把一个向量复制到三个索引。文本先被分为模型词元；一个中文词可能对应多个子词，词元不能直接等同于自然语言词。

通道一个计算窗口产生什么当前如何存入索引
语义 / Dense一个 1024 维浮点向量每个窗口一行 Dense 记录，归属于原物品。
稀疏 / Sparse词元编号 → 非负学习权重；只保存非零项每个窗口一行稀疏记录，倒排项保存词元编号及权重。
多向量 / ColBERT多行 1024 维词元向量，数量随文本长度变化每个词元向量单独一行，记录所属物品、来源修订及窗口位置。

一本书怎样进入这三路

  1. 保留原书、完整正文和自然章节。Worker 按章节顺序读取，示例配置每次最多读取 2048 个 Unicode 码点的计算窗口，不重叠；不会把窗口写成独立推荐物品。
  2. 推理服务再按模型的 token 上限划分输入；示例模型上限 8192 token，包含模型所需的特殊 token。计算窗口的码点数与模型 token 数是不同单位。
  3. 每个模型片段同时返回 Dense、Sparse、多向量，并记录相对于输入的起止位置。Worker 把位置加回章节偏移，关联不可变来源修订。
  4. 书籍／文章的根物品使用各正文窗口编码；概念、事实等语义物品另外编码其有原文依据的引用文本，不是拿生成摘要代替原文。
  5. 表示矩阵存入对象存储作为计算产物，并写入对应索引。摘要递归聚合是另一项内容产物，目前没有再把所有窗口向量训练聚合为一个整书向量。
当前物品身份完整，检索表示仍是多组局部表示。“整物品保存”不能写成“整本书已被压成一个全局向量”。同一原文中的语义对象会单独编码，其向量会增加容量，不与根物品表示自动去重。

03 · 语义：向量、索引与评分

1. 表示怎样产生

模型输出每个词元的上下文隐藏状态。当前 FlagEmbedding 默认取序列首位置的表示（CLS pooling），再作 L2 归一化，得到一个 1024 维向量。查询端与物品端使用同一个已选定的模型配置和表示空间。推理配置未改变这一默认池化方式。

d = h首位置 / ‖h首位置‖₂
score(q, d) = q · d = Σ qidi

双方归一化时，内积等于余弦相似度。它表示模型学到的语义接近程度，不是“正确概率”，也不是点击率；例如表述不同但意思相关的句子可能靠近，这种效果仍需真实语料评测。

2. 索引与查询怎样执行

  1. 每个正文／语义对象窗口写一条 Dense 向量行；后端配置为 Milvus DISKANN，度量使用 IP。
  2. 查询由问题、上下文及图画像文本拼成，再生成查询向量；若查询本身分成多个片段，每片各查一次。
  3. 每次 ANN 查询只检索服务器场景允许的根物品类型，取 K 条向量行。同一物品可能占用多条。
  4. 按“物品＋来源修订”合并命中行，当前取所有已命中窗口／查询片段组合中的最大内积作为该物品的 Dense 分；保留对应窗口位置。
当前物品分 = max { 已返回的查询片段向量 · 该物品窗口向量 }

3. 数值例子

仅为二维算例：q=(0.8, 0.6)，A=(1, 0)，B=(0, 1)，三者长度均为 1，因此 A 得分 0.8、B 得分 0.6。实际模型为 1024 维；这里只演示内积，不是模型预测。

当前没有整书全局 Dense 聚合或跨窗口求平均；采用最佳局部命中。DISKANN 是近似近邻，返回集合不保证等于穷举结果。物理 Milvus 的召回误差尚未实测。

04 · 稀疏：学习权重与倒排

1. 权重怎样产生

对输入中每个词元的上下文状态，模型的稀疏头作线性映射，再经 ReLU 得到非负权重。同一个词元编号出现多次时取最大权重；去掉指定特殊 token 与零权重，最终只保存非零的“词元编号、权重”对。

w(t) = max输入中编号为 t 的位置 j ReLU(线性映射(hj))

编号来自模型词表，不是项目手写标签，也不是业务实体 ID。当前是 BGE-M3 学习型词法权重：只对输入中出现的有效 token 保留权重，没有在 BTW 中额外计算词频、逆文档频率或 BM25 长度归一化。词元相同才能在稀疏内积中直接贡献分数；上下文影响的是权重。

2. 倒排怎样检索

  1. 稀疏字段存入 Milvus 的稀疏向量列，索引是 SPARSE_INVERTED_INDEX，度量是 IP；当前构建参数不主动丢弃最低权重项。
  2. 每个词元对应一组含有该词元的窗口记录与权重。查询的非零词元访问相应倒排项，累加相同词元的权重乘积。
  3. 按场景根类型过滤后返回 K 条窗口候选，再按“物品＋修订”归并。当前保留最佳窗口分，不把一本书所有窗口的稀疏权重先累成一份全书词袋。
窗口分 = Σt ∈ 查询词元 ∩ 窗口词元 w查询(t) × w窗口(t)
当前物品分 = max { 已返回窗口的稀疏内积分 }

3. 数值例子

演示词元查询权重窗口 A窗口 B
词元甲0.80.70.2
词元乙0.400.9
词元丙00.60

A = 0.8×0.7 = 0.56；B = 0.8×0.2 + 0.4×0.9 = 0.52。丙只在 A 出现，不贡献匹配分。这些是手工演示权重；实际编号和数值由模型产生。

此通道用于保留细粒度词法匹配信号，不能用 BM25 分数替换后仍称其为相同算法。跨章节分别出现的查询词，目前不会自动合并成一个全书 Sparse 分。

05 · 多向量：独立召回与聚合

1. “多”指什么

一个窗口中的多个词元分别保留上下文向量。当前模型对首位置之后的隐藏状态作 ColBERT 线性投影，再逐向量 L2 归一化；去除填充位置。默认投影维度为 1024，当前库的后处理没有再单独移除末尾 EOS，因此实际行数以返回矩阵为准。

它不是“用多个模型生成多个整段向量”，也不是“给物品多贴几个标签”。同一个词元在不同上下文中可有不同向量。

Q = [q₁, …, qM]，D = [d₁, …, dN]
完整 MaxSim(Q,D) = (1/M) Σi maxj(qi · dj)

含义是：每个查询词元都在文档中找最相似的词元，最后对查询词元求平均。多个查询词元可以命中同一个文档词元，不要求一一匹配，也不要求命中位置连续。

2. 当前在线算法：词元独立召回，再按物品聚合

  1. 索引写入：把每个文档词元向量单独写入多向量集合，用 DISKANN + IP 检索；每行保留物品、根类型、修订、章节及窗口区间。
  2. 查询展开：把所有查询片段的词元向量合并为一个查询向量序列。每个词元分别检索全体允许物品的子向量，并非只查询 Dense 已召回的候选。
  3. 单词元归并：在这个词元返回的 Top-K 子向量行中，同一物品／修订只保留最高分；同一书的不同窗口可以参与。
  4. 跨词元聚合：各词元对该物品的最佳命中分相加，除以全部查询词元数，得到物品分。某词元没有召回该物品时，当前代码贡献 0。
  5. 列表与位置：按聚合分取最多 K 个物品；返回最高单次命中行的窗口位置，并标明 ANN 多向量近似路径。
Ni = 第 i 个查询词元召回的 Top-K 子向量行
besti(x) = max { qi · d | d ∈ Ni 且属于物品修订 x }
未命中时 besti(x) = 0
线上分(x) = (1/M) Σi besti(x)

3. 一个跨章节例子

内积演示值第一章的向量第二章的向量
查询词元甲0.900.10
查询词元乙0.200.80

如果两次词元检索都找到最佳子向量，线上聚合为 (0.90+0.80)/2 = 0.85，两个贡献分别来自两章。若乙的 Top-K 没有该书，当前近似分变成 (0.90+0)/2 = 0.45。

线上聚合 0.85；单窗口参考 0.55。

纯算术演示，不调用模型，不代表实测召回率。单窗口参考列始终使用完整已知矩阵。

4. 当前精确参考与线上还有一个实质差异

测试用的精确参考会对每一对查询窗口、文档窗口计算完整 MaxSim，然后取最高的窗口对得分。线上实现则对全部查询词元求平均，允许每个词元跨文档窗口命中。因此即使 ANN 找全邻居，两者仍可能不同。

现有参考物品分 = max查询窗口 a, 文档窗口 b MaxSim(Qa, Db)
上述例子的参考分 = max((0.90+0.20)/2, (0.10+0.80)/2) = 0.55
这里不能只写“ANN 有近似误差”。还存在跨窗口聚合口径差异；当前参考实现不是线上物品级公式的严格等价基准。未命中按 0 计也不能解释为真实相似度为 0；存在负内积时，不保证它是完整 MaxSim 的下界。

查询矩阵来自“问题＋上下文＋图画像文本”的统一编码。当前聚合对这些返回词元使用同一平均规则，没有另外给问题词元和画像词元设置不同权重；画像文本变长也会改变分母与匹配结果。

5. 原文定位的实际粒度

虽然按词元检索，索引行保存的是窗口区间，没有保存每个 token 的精确字符偏移。一个物品当前只返回一处代表窗口；跨章聚合得分不等于已经交付全部跨章证据。有据问答和计划仍需继续检索／读取相应原文。

06 · 预算、融合与排序

环节当前示例／实现实际含义
模型BGE-M3；Dense 与多向量当前均 1024 维同一编码器同时输出三种表示；不是三个生成模型。
离线输入每窗口 2048 码点；模型上下文最多 8192 token两个独立边界；原文位置保持连续，窗口不成为推荐物品。
每路预算示例 K=100；返回列表最多 20，计划最多 10K 首先是每次向量检索的行数，再用于物品候选截取；不保证得到 100 个不同物品。
多向量查询示例最多 1024 个查询子向量超限时该通道返回错误，不静默截断；其他路成功时返回部分通道结果。
检索并发不同通道并行；一个通道内部各查询向量顺序调用 SDKM 个查询词元会触发 M 次多向量搜索请求；不是已实现一次批量 ANN。
建库写入示例批量 256 行多向量的批次按子向量行计数，不是按完整书籍数计数。
融合RRF 的示例常数 k₀=60按各路排名融合，不把 Dense、Sparse 和多向量原始分直接相加。
RRF(x) = Σ有效通道 c 1 / (k₀ + rankc(x))，排名从 1 开始

例如一个物品的三路排名是 1、3、2，融合分为 1/61 + 1/63 + 1/62 ≈ 0.048395。它是排名融合分，不是相关性概率。候选先核对有效修订；当前融合使用各路原始排名位置，过滤过时行后不会重新压紧排名。

配置真实排序模型（当前实现为经 DataCenter 的 LightGBM 排序，非生成模型）后，模型使用 Dense、Sparse、多向量、RRF、图画像匹配、质量及缺失标记等特征重新排序。这里的三路原始分保留其各自含义。跨通道融合时代表位置目前沿用第一个创建该候选的通道位置；不保证是多向量累计贡献最大的全部位置。

07 · 推荐怎样使用这些表示

本页三路表示与上述公式直接用于推荐，推荐并没有另外生成一套“推荐专用假向量”。差别在输入、候选范围、排序目标及交付。

路径实际计算
图画像路径节点标签、关系及属性组织成文本，与当前上下文一起编码。当前是确定性文本组装，不是图神经网络用户塔。
匹配用户表示仅在已有物品投影、匹配索引、用户空间和维度均适用时启用。每个物品窗口的 Dense 经训练投影并归一化，与外部固定用户向量作 IP 检索，再加入 RRF。
用户向量幅值外部用户向量在 Go 查询端没有再次归一化，因此该匹配分首先是 IP；不能无条件称它为余弦或概率。
第四路与排序匹配通道影响候选和 RRF；当前排序特征没有单列匹配原始分，影响主要经 RRF 和候选集合传入。
只有用户向量当没有图画像／查询文本但存在合格用户表示时，可只走匹配通道。缺少所有可用输入时明确失败，不补模拟画像。
网站／计划网站三路及匹配通道召回前都排除书籍；计划按服务器允许的资料范围取证。网站不调用生成模型。

08 · 召回与排序

推荐复用同一套物品检索。图画像与当前上下文组织查询后，由 Dense、学习型 Sparse、多向量独立召回，再用 RRF 融合；如果外部用户表示与物品投影相匹配，还可加入独立的用户匹配通道。

位置当前行为
召回前服务端资料范围下推到每个通道。网站仅允许根类型为文章，书籍及书内衍生对象不进入候选。
候选返回后批量核对有限候选的当前可见修订，排除删除和过期内容。
融合与排序各路排名经 RRF 融合；部署了推荐排序模型时真实推理，否则明确保留融合排名。
网站交付归并到根文章并按重复簇去重，最后截取结果数量。
计划交付排序后读取原文，进入生成和引用交付；不经过网站列表的根文章去重分支。

多向量先检索子向量再聚合物品，线上 ANN 聚合得分标记为近似；完整矩阵可供离线数值计算，但现有参考的跨窗口口径尚未与线上统一，不把所有书籍矩阵常驻在线内存。

09 · 画像与场景

每次请求提供 request_id、ontology、scenario、query/context 和 limit。场景由服务端配置，限定资料范围、候选数量、排序目标与计算预算；客户端不能扩大范围或提交任意排序公式。Ontology 是外部图画像，不是访问授权，也不在 BTW 中重新生产。

用户表示可选：空间、维度和已部署的物品塔／索引均匹配时才参与计算。缺失或不匹配时使用图画像驱动路径，返回实际使用路径，不制造替代向量。

10 · 有据计划与流式交付

  1. 用例确定范围、当前环境与预算，再启动实际 Runner；每次运行使用独立会话，结束后释放。
  2. 「生成」节点是本轮唯一的大模型调用：每轮工具调用返回后由模型继续决策，形成图中虚线循环；当前默认预算为最多 8 次模型调用、6 次工具调用，证据读取受场景字节预算约束，超限或解析失败按错误结束，不静默截断。
  3. 搜索和原文 Function Tool 直接复用领域能力，模型参数不能扩大服务器范围；计划场景不接受搜索等级，搜索三档的查询规划器与证据判断器不参与推荐。
  4. 预读和工具读取的正文形成证据集合，引用必须来自该集合并能按位置回读。
  5. 终态解析回答／计划的结构；不存在的引用、缺失计划字段或模型错误均不能变成成功。
  6. SSE 分别输出过程、模型增量与完整终态；局部模型完成不提前结束工具循环。
本轮真实模型联合验证：保存原文 → 模型理解 → BGE 表示 → 精确参考检索 → 计划 → 引用逐条回读，已经通过。它不等于物理 Milvus 或大规模生产验收。

当前 tRPC-Agent-Go 版本在 Session 时间戳更新与工具快照间的竞态，经公共 Session 接口适配，并由实际工具调用的 race 回归保护；没有修改模块缓存或复制框架内部事件循环。

13 · 反馈与训练

推荐排序

推荐使用独立于搜索的排序目标。候选、曝光、点击及明确反馈关联实际请求、物品、位置、场景和模型配置；未经展示的物品不直接作为负反馈。

物品塔

固定外部用户表示，只训练物品侧投影。样本需标明基础物品模型、表示空间和外部用户空间；维度相同但空间不匹配仍不可参与匹配。

缺少合格用户表示或行为样本时明确报告未训练，继续使用图画像驱动检索。线上线下使用同一特征定义，遵守完整来源／重复簇隔离及行为观察窗口。

一次请求使用进入时从 DataCenter 取得的表示合同及 BTW 自身索引。DataCenter 改变模型空间后，BTW 必须在新环境完成表示编码、索引构建与来源变化追赶，再由部署平台整体切流。

BTW 导出有来源隔离的训练样本；模型训练、物理装载和激活归 DataCenter。训练成功不自动改变 BTW 已建索引，表示空间变化需要同步重建和验收。

已验证真实排序训练、加载，以及固定用户物品投影；没有生产用户行为数据，因此不宣称已经获得个性化收益。

14 · 实现边界与待完善处

以下是从当前代码核对出的状态，未在此次文档修改中改算法：

当前已实现尚不能据此宣称
正文窗口／语义引用各自编码，归属整物品没有学得的跨章节全书表示聚合；Dense 和 Sparse 是最佳局部命中。
多向量每词元独立召回后按物品聚合现有离线参考与线上聚合不严格一致，尚不能宣称线上数值等价验收通过。
所有返回的文档子向量写入磁盘索引，原矩阵另存对象存储没有文档词元压缩、剪枝、固定子向量配额或成熟的长书索引成本控制。
ANN 返回 K 行后才做物品归并同一长书的多行可占据较多返回名额；尚无物品级分组召回或自适应补候选机制。
查询有 token 上限，通道分开执行通道内逐词元网络调用；大查询的吞吐和尾延迟仍待优化及实测。
有向量、稀疏内积和小样本框架测试尚无物理 Milvus 完整验收和真实百万／亿级质量、资源实测。

容量必须按真实子向量数计：当前每行 1024 个 float32，原始向量约 4096 字节。某窗口若返回约 2000 个子向量，仅该矩阵就约 8.2 MB；还没计索引、元数据、副本、JSON 中间产物和语义对象的重复编码。此前“平均 32 子向量／物品”的亿级容量表只是输入假设，不是现有实现对长书的实际子向量数量。

15 · 错误与恢复

故障／竞态约定结果
对象成功，数据库失败不确认输入；元数据事务回滚，原文件残留经带宽限期的受控孤立对象清理。
数据库成功，消费确认失败相同事件重放返回原接纳结果，不重复创建修订与任务。
旧事件或旧 Worker 迟到不能覆盖新修订或重新激活删除内容；租约尝试标识只在真实提交处生效。
资料更新旧可检索修订保留到新修订完成；旧索引修订异步清理，原文历史保留。
资料删除元数据立即隐藏；索引清理可重试，候选有限可见性核对防止旧数据泄漏。
模型／索引不可用真实失败；部分通道可用时明确降级路径，不以空结果或伪分数冒充成功。
用户取消／写出失败取消本轮运行并收尾；共享 Runner 与存储由进程 owner 关闭。
