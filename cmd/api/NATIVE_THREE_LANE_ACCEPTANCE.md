# 正式搜索 API 的原生三路物理后端交接

当前 BTW 独立叶子从搜索开发远端 `8edaca88e60a84d5ea0e3566de475a8d1a072944` 开始。写区 `[W1]` 为本叶子 `cmd/api` 的配置、物理装配与验收入口，以及 test-only 的 `internal/transport/http/search` 交接和 Scope 取消分类；只读区 `[R1]` 为三 lane、内容 Build、RTW/DC 当前开发树与 Sea-Docs。依赖 `[D1]` 是根 `go.mod` 已解析的 Milvus Go SDK `v2.6.2`、tRPC-Agent-Go 核心 `v1.8.1` 与锁定 Milvus Lite wheel；生成物 `[G1]` 不手改；外部 `[X1]` 仅待任务自建的本机 RTW/DC/PG/Lite/对象目录，生产和用户已有实例均不写；范围外 `[N1]` 为 BTW/RTW/DC 开发集成树、Docs 与其他脏工作树；临时 `[T1]` 为验收一次性目录。主职责 `[C6]` 物理配置/SDK 装配，跨 `[C2]` 搜索、`[C7]` RTW发布ABI、`[C5]` 现有原生Graph/Runner、`[C8]` 验收。

`BTW_SEARCH_MODE=native-milvus` 必须显式设置，另给 `BTW_SEARCH_MILVUS_ADDRESS` 与一份直接可读的 `BTW_SEARCH_NATIVE_FILE`。该 JSON 严格是 `sea.search.native-milvus.v1` 的 `engine=lite|milvus`、`namespace`、Dense 与 Multi-vector 各自 `m/ef_construction/ef_search`；重复、转义别名、未知字段和隐式 exact fallback 均拒启动。Lite 的既有 lane 构造 ABI 是 Dense/Multi `Engine=lite`、学习型 Sparse `Engine=native-lite`，Standalone 三者均为 `milvus`。Collection digest 同时包含当前 IndexRef 与这份完整物理配置；RTW v1 `IndexManifest` 只签三个 Lane Ref/Profile/Probe，**没有**物理 namespace/HNSW 收据，故正式内容 worker 仍须在 READY 之前另将物理资格冻结到同代权威清单，不能从 Ref 猜物理集合。

Native 模式的 RTW HMAC Scope 先照旧验证。进入 Runner 或用户 BGE 查询前，API 再从 RTW Worker 重读**当前人工激活**的 Snapshot，核签名版本、三个不同的完整 LaneIndex Ref/同 BuildID、generation、ChunkManifest、配置的模型/词表空间及有效 SourceRevision 全集；Multi 必须是 `mask=valid` 和固定 MaxSim 聚合。随后只读 `Load` 三个既有 Dense HNSW、学习Sparse倒排IP、token-row HNSW/IP Collection，逐个回核字段/index/行并以固定来源执行一条冷加载 probe，再缓存不可变 Snapshot 交原 `search.Service`。请求的三个 lane 在同一 Graph 中独立 Query/候选/RRF，Multi 从自身**全有效范围 token index**得到 chunk 候选后读取完整矩阵做 MaxSim。物理缺行、错Ref/空间/mask、源撤回、取消或探针失败不会产生用户证据或 RTW 引用提交；缓存最多四个已加载发布快照，新代超过上限要求显式重启，不驱逐在途旧快照。旧 `local-exact` 没有物理设置时的启动、签名/Tools/summary、tRPC-Agent-Go 原生Span与结构JSON日志均保持原行为；配置的 Milvus凭据从启动错误脱敏。

当前验证层级：本叶子配置、同代来源/掩码/错lane/错代/缺物理投影与取消前门禁的聚焦 race 已通过，受影响 `cmd/api`、`internal/search`、搜索 HTTP 三包 race、vet、`go mod verify` 与 `git diff --check` 通过；实际三Collection同进程及真RTW×DC×BTW父轮**仍待执行**。本仓 test-only `native_lite_owner.py` 从任务私有目录启动并保活一套固定 Lite `3.2.1`，写0600/O_EXCL的 runtime/stop；`real_index.native_runtime` 仅在显式四来源父轮启用，在RTW READY前用真DC BGE三输出先得完整 exact 编码Ref，再以三个原生 `Build(ResumeIndex:&Ref)`零新编码投影/各自Probe/Load，同三Ref交RTW接纳。输出 `native_projection` 另含确切endpoint、runtime/binary SHA与供正式API重用的物理设置，但明确 `physical_qualified=false`，不自动改变已发布指针。

独立发现见证 `TestRTWNativePublishedIndependentMultiDiscovery` 只在 RTW测试管理员另建无Wiki的四份SourceRevision/四chunk Release、Build READY并人工激活后运行。四段测试文字来自固定合成 BGE 对照输入，查询 `apple pie recipe`，每路 TopK2；前置全候选精确oracle指 Dense=`apple,banana`、学习Sparse=`apple`、Multi=`apple,orange`。真运行必须按本轮 RTW RevisionID/ChunkID重新映射、经**同一Lite 3.2.1** Native Load/Query核实际候选，且由 RTW Worker same-revision SourceReader及当前撤回状态核 Orange 原文/定位/对象哈希；若 ANN 没发现 Orange，本门禁保持红，不拿旧版本 Lite 的独立测试拼成功。见证结果是0600/O_EXCL私有文件，`qrel_evaluable=false,physical_qualified=false,production_verified=false`，不把合成文字宣称为真人 qrel。最终全站文章语料、正式三路物理资格、详搜/高档十二格、Collector及规模成本/SLO均仍需独立交接。
